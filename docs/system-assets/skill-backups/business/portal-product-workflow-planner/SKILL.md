# Portal Product Workflow Planner

Use when Derrick wants to turn a manual service into a productized portal or semi-automated workflow.

## Core intake blocks
- customer identity
- offer/package chosen
- payment step
- upload assets (photos, logos, mascots, flyer, reference links)
- style/vibe selection
- output type selection
- contact/delivery destination

## Core backend blocks
- payment confirmation
- asset storage
- job creation
- prompt/brand-DNA generation
- human QA checkpoint
- delivery/export
- revision loop
- job status tracking

## Output format
Return:
- portal purpose
- intake form fields
- backend workflow steps
- human vs automated steps
- minimum viable stack
- what to delay until later

## Rules
- Start with the smallest useful portal
- Keep humans in QA until quality is proven
- Separate intake, generation, review, and delivery clearly
